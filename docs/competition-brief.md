# Hyacintech STEM 探究学习平台 · 项目说明书

> 一句话定位：**一个会自己变好的 AI 科学探究导师**——学生在课堂里完成六阶段科学探究，这个过程本身产出经过治理的训练数据，回流改进导师模型，再回到课堂。

---

## 一、要解决的问题

上海市初中科学课程标准要求学生完成完整的科学探究：提出问题、设计方案、收集数据、分析论证、形成报告、反思改进。现实中这件事很难做：

- **教师侧**：一个班 40 人同时做探究，教师无法逐个跟进每人卡在哪一步。批改一份探究报告要看方案是否合理、数据是否真实、结论是否由数据支撑——单份 15 分钟以上。
- **学生侧**：卡住的地方高度个性化。有人不会把兴趣变成可研究的问题，有人分不清自变量和因变量，有人有数据但不会从数据里读出结论。传统教学给不出这种一对一响应。
- **现有 AI 产品侧**：绝大多数是"套壳问答"——把大模型接进一个聊天框。它能给答案，但**给答案恰恰是探究教学最该避免的事**。而且它是静态的：用一年和用一天,导师能力完全一样，课堂里积累的宝贵教学交互全部蒸发。

我们要解决的不是"让 AI 回答科学问题"，而是**让 AI 用苏格拉底式追问陪学生自己走完探究，并且让这个陪伴过程可验证、可改进**。

## 二、解决方案：两个嵌套的闭环

### 内环 · 教学闭环（学生一次完整探究）

```
选题定向 → 方案设计 → 过程执行 → 数据分析 → 报告成型 → 结果反思 → 完成
  P1        P2         P3         P4         P5         P6
```

六个阶段不是"聊天话题的切换"，而是**服务器所有的产品契约**。每一次阶段推进都由服务器判定，客户端说了不算：

| 关口 | 服务器凭什么放行 |
|---|---|
| P1→P2 | 学生确认的研究问题 + 与该问题内容哈希绑定的确认动作。问题一改，确认自动失效。 |
| P2→P3 | 服务器组装完整方案预览 → 学生按 `draftHash` 确认 → 提交 → 教师审核通过。哈希过期即拒绝。 |
| P3→P4 | 服务器端核验的安全问答通过 + 锁定表结构的必填单元格全部填满。 |
| P4→P5 | 至少两条**不同的证据指纹**，每条都必须引用学生自己提交过的真实单元格值。复读同一句话、只报行号、编造数值都不计数。 |
| P5→P6 | 教师给出 0–10 有限分数且 ≥6。低于 6 分自动转为软驳回，学生留在 P5 重写。 |

这是整个产品最硬的设计决定：**AI 可以引导，但不能替学生完成任何一个关口**。所有阶段产物、确认哈希、安全核验、证据指纹、状态跃迁都在服务器侧，任何客户端声明一律不采信。

同时保留一条**审计化的旁路**——教师放行。学生真的卡死时，教师可以放行其当前所在的 P2/P3/P4/P5，必须填写不少于 10 字的理由，系统写入 `stageData.timeline.releases` 与 `DataLabAuditLog(STAGE_RELEASED)` 双重留痕，**且该阶段的对话轨迹永久失去成为正面训练样本的资格**。P1 不可放行，因为服务器不能替学生编造研究问题。

### 外环 · 数据闭环（课堂使用 → 模型改进 → 回到课堂）

```
正式会话（每一轮都写 GenerationTrace）
  → 授权与范围检查（学生可授予/拒绝/撤回，与课业成绩完全解耦）
  → 隔离候选 RAW_QUARANTINED
  → 本地脱敏 + 精确/近重复检查 → REDACTED
  → 管理员在只看脱敏快照的前提下提名 → NOMINATED
  → 标注员独立纠正（不能改自己写的稿）→ HUMAN_CORRECTED
  → 工作量审核 + 匿名仲裁 → APPROVED
  → 不可变发布（manifest v3，逐条记录训练资格）→ RELEASED
  → 外部算力平台训练 → 结果登记 ModelRecords → TRAINED
  → 双盲评测 + 六阶段非退化门禁 → EVALUATED
  → 10% → 30% → 100% 灰度，每级有在线观测门禁 → PROMOTED
  → 新模型进入课堂，产生新一轮轨迹
```

**这条环里最反直觉、也最关键的一条原则：线上模型自己的原始回答，默认不是训练正样本。**

模型自评好、学生顺利过关、教师批准通过——这些都只是"值得看一眼"的信号，不等于导师那句话说对了。只有经过独立人工实质性纠正并复核的回答才能进 SFT；原回答与纠正回答可以配成偏好数据的 rejected/chosen 对。人工判定"无需修改"的回答进入较低置信等级，不能靠自评升级。否则模型会把自己的错误当成正确答案反复强化——这是自我改进系统最常见也最致命的失败模式。

## 三、核心创新点

### 1. 课堂使用即数据生产，且不牺牲任何一方

绝大多数教育 AI 产品的数据是"买来的"或"标注外包造出来的"，与真实课堂分布有系统性偏差。本平台每一次正式对话都产出一条不可变 `GenerationTrace`，记录阶段契约、Prompt/抽取器版本、允许与实际选择的追问焦点、交互类型、状态修订与哈希、服务器产物、请求指纹。这些是最真实的教学交互数据。

同时**学生完全不承担代价**：默认 `dataContributionMode=DISABLED`；开启的作业为学生创建 `PENDING` 授权，学生可授予、拒绝、随时撤回，撤回的候选在启动标注活动和组装发布时都会被排除；整个选择与课业成绩零关联。Guest 体验模式的数据完全不落库，也不参与回流。

### 2. 训练资格是算出来的，不是声称的

标注员提交纠正时要声明变更类型（无变更 / 轻编辑 / 实质纠正 / 重写）。服务器用 `trainingEligibility.ts` 独立计算文本与结构差异指标，**把轻编辑包装成重写会被直接驳回**。发布清单 v3 逐条记录每个样本的训练资格，并据此产出经过资格过滤的 `training` 与 `preference` 两套文件。非草稿训练登记还要重新计算当前授权状态、泄漏检查和纠正资格——过去合格不代表现在合格。

### 3. 部署门禁按六个教学阶段逐段验收

一个候选模型要上线，`deploymentGate.ts` 要求它同时满足：训练血缘就绪、评测产物完整且已核验、**六个阶段逐段覆盖且逐段非退化**、无 critical 错误、评审一致性可接受、结构解析成功率不劣于基线。只有 `ELIGIBLE` 的模型才能进入 10%→30%→100%，每级之间还有在线观测门禁（会话数、结构失败率、教师驳回率、早退率对比基线）。

灰度期间用**稳定会话哈希**分配模型并持久化到 `Conversation.deployedModelVersionId`——同一个学生在同一次探究里不会中途换模型。回滚会创建 100% 基线部署并把仍在用故障候选的会话重新钉回基线。

### 4. 数据集从零重建，不复用被污染的历史

六阶段漂移审计发现历史 489 条记录存在阶段边界混淆，我们没有选择"打补丁重标"，而是把它整批标记为 `LEGACY_QUARANTINED`，只允许用于生成场景、构造 rejected 负例或回归用例。新的 `stage-contract-v3/v4` 案例从批准的输入重新生成，带完整来源标记。扩产走阶梯门禁：**Smoke 6 → Calibration 12 → Trial 36 + 人工签署 → Full 180**，上一级没通过就不能开下一级。

历史发布和轨迹是不可变的历史数据。新的阶段契约用新生成的案例和明确的来源标记，绝不从旧发布派生或重贴标签。

## 四、系统架构

```
┌─ 学生端 ────────────────┐   ┌─ 教师端 ──────────────┐
│ ConversationWorkspace   │   │ 待审队列 / 审核详情    │
│  ├ ConversationChat     │   │ 「可能卡住的学生」     │
│  └ 阶段面板             │   │  ├ 审核通过/驳回+评分  │
│    P2 SchemaEditor      │   │  ├ 留痕放行            │
│    P3 DataTableEditor   │   │  └ 正样本提名          │
│    P4 ChartViewer       │   └───────────────────────┘
│    P5 ReportViewer      │
│    P6 Stage6Panel       │   ┌─ Data Lab（annotator/reviewer/admin）─┐
└─────────────────────────┘   │ TopicCard 编译 → 阶梯扩产            │
            │                  │ A/B 候选 + 交叉批判                  │
            ▼                  │ 首审 → 终审 → 不可变发布下载         │
┌─ 服务器权威层 ──────────┐   │ 模型登记 / 评测导入 / 灰度部署        │
│ 阶段门禁 canAdvance     │   └──────────────────────────────────────┘
│ 服务器产物 stageArtifacts│              ▲              │
│ 安全 checkBlacklisted…  │              │              ▼
│ 追踪 callLLMWithTrace   │──── 授权回流 ┘        外部算力平台训练
│ 一事务提交 persistTurn  │
└─────────────────────────┘
```

**关键工程决定：**

- **事务原子性**——展示消息、阶段数据/推进、生成轨迹在同一个 `$transaction` 里提交。LLM 调用失败则一个字都不落库，不存在"消息存了但轨迹丢了"的中间态。
- **提示词版本钉死**——执行严格按会话/模型记录的 `promptPolicyVersion` 分发，绝不静默换成全局当前版本。生产 Tutor 固定在 v1，候选 v2.3 必须通过 Data Lab 全套门禁才能提升。
- **学生可见状态最小化**——TopicCard 答案键、隐藏评分量表、Critic 输出、评审专用证据永远不进入 Tutor 可见状态。编译视图严格区分学生可见与隐藏桥接信息。
- **零依赖自研**——沙箱无 npm 源，因此手写了 `app/lib/zip.ts`（基于 zlib 的 ZIP）、`app/lib/docxExtract.ts`（替代 mammoth）、`app/lib/llm/jsonRepair.ts`（替代 jsonrepair）。运行时依赖仅 9 个，无任何 LLM SDK——直接走 HTTP，可对接任意 OpenAI 兼容网关。

**技术栈**：Next.js 16.2.6 App Router / React 19.2.4 / TypeScript / Prisma + SQLite / iron-session / Recharts。

**规模**：40 个数据模型、20 个已提交迁移、107 个 API 路由、36 个页面、约 5.4 万行 TypeScript。

## 五、可验证的工程完整性

项目没有引入测试框架（沙箱限制），改为 46 个可独立运行的确定性测试脚本，全部用 `npx tsx` 执行：

| 套件 | 覆盖 | 结果 |
|---|---|---|
| 纯函数套件（14 套） | 阶段门禁、抽取、审核状态机、限流、JSON 解析、节奏控制、表结构归一化、Word 导出、分页谓词等价性、放行链 | **252 条断言全通过** |
| `data-lab:test`（21 套） | Tutor 语言流水线、阶段契约、数据集 v3 对抗门禁、风格策略与持久化、生成轨迹、生产候选、训练资格、部署门禁、工作量审核、活动生命周期、账号生命周期、TopicCard V2、端到端启动集成 | **507 条断言全通过，连跑两遍幂等** |

测试全部包含**反向哨兵断言**——不只验证"该通过的通过了"，还验证"该拒绝的确实被拒绝了"：低于 10 字的放行理由被拒、非当前阶段不能放行、P5 放行必须带真实评分、普通审核通过不得写放行轨迹、已确认方案不被系统补的表覆盖、PILOT 数据即使被误标 SFT_ALLOWED 也不能发布、未通过 Smoke 6 不能开 Calibration 12。

数据库相关测试强制跑在专用一次性 `DATABASE_URL` 上，测试自身负责清理并恢复它临时改动的生产部署状态。

## 六、实现进度与真实运行数据

平台已完整跑通，不是原型：

- **教学侧**：真实小规模试用中，库内 12 个学生账号、7 位教师、7 份真实作业会话、86 条生产 `GenerationTrace`。
- **数据侧**：123 个 `TutorTurnCase`、77 条经双人审核的定稿轮次。
- **模型侧**：已登记运行模型与生产基线，1 条 `PRODUCTION / ACTIVE / 100%` 部署在线。
- **线上环境**：nginx 反向代理，可通过外部域名访问。

已完成的里程碑：六阶段教学流程与服务器权威门禁、Data Lab 三角色工作台、生产数据授权回流、训练资格计算、发布清单 v3、模型登记与评测导入、部署门禁与灰度回滚、活动生命周期治理、教师放行与卡住学生可见性。

## 七、教育价值（真人分享支撑材料）

- **对齐课标**：六阶段直接对应上海市初中科学课程标准的探究要素，不是自造流程。
- **减负而非替代教师**：教师看到的是"谁卡在哪一步、服务器判定的具体阻塞原因是什么"（连续 8 轮未推进即进入「可能卡住的学生」列表），而不是 40 份原始聊天记录。审核界面直接呈现平台字段、嵌入数据表、被接受的分析证据、AI 参考评分——教师的注意力花在判断上，不花在信息搜集上。
- **AI 参考分不替代教师分**：`generateReferenceScore` 给出 1–10 总分与五个维度（完整性/逻辑/数据运用/创新/表达），但**只有教师分数决定 P5→P6**。AI 评分失败时返回 `null`，永远不阻塞学生提交。
- **安全监护贯穿全程**：每次调用 LLM 前跑黑名单检查；P2 确认时服务器派生风险点与安全问答，P3 入口主动补齐，答案键只在服务端校验。
- **两种入口**：`/experience` 免注册直接体验（不落库、IP 限流），正式账号走班级/作业/教师审核完整链路。

## 八、可推广性（真人分享支撑材料）

- **学科可迁移**：六阶段是科学探究通法，TopicCard V2 作为编译输入把学科内容与流程解耦——换学科等于换一批 TopicCard，不改流程代码。
- **部署成本低**：单进程 Next.js + SQLite，一台普通服务器即可承载一所学校；无向量库、无消息队列、无 LLM SDK 锁定。
- **模型可替换**：只要是 OpenAI 兼容网关都能接；`resolveConversationModel()` 支持多模型并存与按会话稳定分配，学校可以自选或自训模型。
- **训练与推理解耦**：训练在外部算力平台完成，平台只做数据出口和结果登记簿，不需要学校自备 GPU。

## 九、已知边界与下一步

诚实说明当前边界：

- 试用规模仍小（7 份真实会话），教学效果尚无对照组量化数据，这是下一阶段的首要工作。
- 生产 Tutor 提示词仍固定在 v1，候选 v2.3 尚未通过完整发布队列门禁，属于设计上的谨慎而非未完成。
- 图片附件默认排除在回流之外，多模态探究记录（实验照片的自动理解）尚未纳入。
- 历史 489 条记录已隔离，新数据集的规模化扩产（Full 180 之后）正在进行。

下一步优先级：扩大真实课堂试用并建立对照评估 → 完成 v2.3 提示词的完整门禁验收 → 多学科 TopicCard 扩展。
